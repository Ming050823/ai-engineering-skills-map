2. 高階工作流：規劃 → 執行 → 部署監控

2. High-level workflow: plan → execute → deploy and monitor

工作重心從「寫程式」轉向「決定做什麼、設計架構、寫 spec、驗證輸出」。

Effort shifts away from writing code toward deciding what to build, designing architecture, writing a spec, and verifying output.

Planning 規劃

Planning

腦力激盪 → spec → 執行計畫。檢視假設、安全與過度設計。

Brainstorm, write a spec, then generate an execution plan. Interrogate assumptions, security, and overengineering.

Execution 執行

Execution

讓 agent 建、測、驗證。關鍵是自主程度與人工監督的平衡。

Have the agent build, test, and verify, balancing autonomy with oversight.

Deploy & monitor

Deploy & monitor

部署後用 agent 看 log、找問題、提出並執行改進。

Deploy, then use agents to watch logs, surface issues, and apply improvements.

3. 五項核心能力

3. The five core skills

3.1 Directing the workflow

決定每一步花多少人力與 agent 時間，以及何時退回前一步。

Decide how much human and agent effort each step deserves, and when to iterate backward.

3.2 Enabling agent autonomy

選自主層級、管 context、決定並行，並用權限與閘門保安全。

Choose autonomy, manage context, run agents in parallel when useful, and set safe permissions.

3.3 Reviewing the work

用測試、審查與證據判斷「做完了」。不要讓實作方自己改弱測試。

Use tests, review, and evidence to decide done. Never let the implementer weaken the verifier.

3.4 Customizing the agent and its environment

維護 AGENTS.md / CLAUDE.md、skills、hooks、MCP。

Maintain AGENTS.md / CLAUDE.md, skills, hooks, and MCP servers.

3.5 Coding agent foundations

看懂 search、context、tool、subagent 與失敗模式，才能及時介入。

Understand search, context, tools, subagents, and failure modes so you can intervene.

起手式

Starting move

先寫好 repo 根目錄的 AGENTS.md（Claude 再加 CLAUDE.md）：test 指令與禁區。這一檔同時服務五項能力。

Write test commands and off-limits paths into root AGENTS.md (plus CLAUDE.md for Claude). That single file serves all five skills.

5. 日常流程

5. Daily loop

  1. Planning。 Plan mode 或 /plan → spec + 分步驗證。
  2. Execution。 小改互動；大改用 goal + 測試迴圈。
  3. Review。 換角色審；測試由你指定。
  4. Customize。 反復糾正寫進 md / skill / hook。
  5. Monitor。 部署後看 log，再走 plan → patch → verify。
  1. Planning. Plan mode or /plan → spec plus a verifier per step.
  2. Execution. Stay interactive on small edits; use a goal plus tests on larger work.
  3. Review. Change roles. You specify the tests.
  4. Customize. Promote recurring corrections into markdown, a skill, or a hook.
  5. Monitor. Watch logs after deploy; re-enter plan → patch → verify.
